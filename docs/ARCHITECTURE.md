# هيكل الموقع وقواعد تطويره

موقع ثابت (HTML + CSS + JavaScript) بلا خادم وبلا خطوة بناء إلزامية، يُنشر على GitHub Pages.
كل ملف له مكان واحد ووظيفة واحدة. أداة الفحص `tools/check.mjs` ترفض أي ملف ميت أو نص غير مستعمل
أو مفتاح ترجمة ناقص، فلا يتراكم شيء مع الزمن.

## خريطة المجلدات

```
index.html, portal.html, …     صفحات مولَّدة من قالب واحد (لا تُعدَّل باليد) ← tools/build.mjs
404.html, offline.html         صفحتا الخطأ وعدم الاتصال (مولَّدتان أيضًا)
sw.js                          العمل دون اتصال (الشبكة أولًا للصفحات والكود). سطر VERSION يكتبه build.mjs
manifest.webmanifest           تعريف التطبيق للهاتف
site.config.json               عنوان الموقع + هل صفحات المعرفة مسودة (noindex)

css/     tokens.css            الألوان والخطوط والمقاسات — مصدر واحد للوضعين الفاتح والداكن
         base.css              العناصر الأساسية: أزرار، نماذج، نافذة الحوار، الطباعة
         shell.css             الرأس، القوائم، التذييل، التنبيهات، البحث، بطاقات الأخبار
         home.css              الصفحة الرئيسية
         content.css           صفحات المحتوى (المعرفة، المواضيع، الدليل)
         portal.css · account.css · history.css   ما يخص صفحة واحدة فقط

js/      boot.js               يعمل قبل الرسم: يحدد اللغة والاتجاه والمظهر. فيه جدول اللغات الوحيد
         core/                 أدوات بلا واجهة: dom · i18n · theme · icons · cms · site · drafts
         shell/                الهيكل المشترك لكل الصفحات: header · footer · dialog · search · news · layout · toast · shell
         pages/                ملف واحد لكل نوع صفحة: home · knowledge · history · portal · account

locales/ ar · badini · sorani · en     نصوص الواجهة (مفاتيح متطابقة في الملفات الأربعة)
data/    knowledge/  history/          محتوى مركز المعرفة والتاريخ: index.js للبيانات غير اللغوية + ملف لكل لغة
content/ *.json                        ما يحرره الموظفون من لوحة الإدارة (أخبار، تنبيهات، إحصائيات، مراكز، قائمة)
assets/  brand/ · photos/ · uploads/   الشعار والأيقونات · صور التصميم · صور لوحة الإدارة
fonts/                                 الخطان المستعملان مع رخصتيهما (SOURCES.md)
admin/                                 لوحة الإدارة Sveltia CMS (config.yml + GUIDE.md)
tools/   build.mjs · check.mjs · review.mjs
docs/    هذا الملف · BADINI.md · DOMAIN.md
```

## كيف تُرسم الصفحة

1. `js/boot.js` (سكربت عادي في `<head>`) يقرأ `?lang=` ثم الاختيار المحفوظ، ويضع `lang` و`dir`
   و`data-locale` و`data-theme` على `<html>` قبل أول رسم؛ فلا تومض الصفحة باتجاه أو لون خاطئ.
2. ملف الصفحة في `js/pages/` يستدعي `startPage({ id, load, render, onCms })` من `js/shell/shell.js`.
3. `startPage` يحمّل ملف اللغة المطلوبة فقط (`import()` ديناميكي) وبيانات الصفحة، يرسم الرأس والتذييل
   ثم المحتوى، وبعدها يجلب `content/*.json` ويرسم الأجزاء القادمة من لوحة الإدارة.
4. تغيير اللغة يعيد الرسم في مكانه بلا إعادة تحميل (`onLocaleChange`).

كل صفحة تعلن وحداتها بـ `<link rel="modulepreload">` (يولّدها `build.mjs` بتتبّع الاستيراد)،
فتُحمَّل بالتوازي. الخطوط والسكربتات والأنماط كلها محلية، فلا يخرج أي طلب إلى موقع آخر عند فتح الصفحة.
الاستثناء الوحيد: فيديو خبر (YouTube عبر youtube-nocookie.com أو Vimeo مع dnt=1) يُطلب عند فتح الخبر فقط،
وصفحة الخصوصية تذكر ذلك.

## قواعد لا تُكسر

| القاعدة | السبب |
|---|---|
| لا نص ظاهر داخل الكود — كل نص مفتاح في `locales/` أو `data/` باللغات الأربع | اللغات لا تتباعد، والمراجعة اللغوية تتم في ملف واحد |
| لا HTML يُكتب بالسلاسل النصية — استعمل `html\`…\`` من `core/dom.js` | يهرّب القيم تلقائيًا (لا ثغرات حقن من محتوى لوحة الإدارة) |
| لا لون ولا خط خارج `css/tokens.css` في الملفات المكتوبة باليد | تغيير واحد يسري على الموقع كله وعلى الوضع الداكن |
| لا `!important` ولا محددات أطول للتغلب على قاعدة — استعمل الطبقات | `@layer base, components, layout` يحدد الأولوية صراحة |
| لا ملف CSS أو JS في جذر الموقع | الجذر للصفحات فقط؛ الفحص يرفض غير ذلك |
| لا تعديل يدوي على ملفات `*.html` | تُعاد كتابتها من القالب؛ عدّل `tools/build.mjs` |
| لا مكتبات خارجية ولا روابط CDN في الصفحات العامة (لوحة الإدارة وحدها تحمّل Sveltia CMS بإصدار ثابت وبصمة تحقق) | الخصوصية، والسرعة، والعمل عند انقطاع الخدمات الخارجية |
| أيقونة جديدة = سطر في `core/icons.js` فقط | مجموعة أيقونات واحدة بسُمك واحد |

`css/shell.css` و`css/home.css` يحملان التصميم المعتمد للصفحة الرئيسية والرأس: مقاساتهما بوحدة
`cqw` (نسبة من عرض `.page`). استُخرجا من الموقع القديم بعد حذف كل قاعدة لا أثر لها، ثم جُمِّدا؛
يُعدَّلان الآن باليد كأي ملف آخر.

## أعمال شائعة

**قاعدة عامة:** بعد أي تعديل في `css/` أو `js/` أو `locales/` أو `data/` أو `fonts/` أو `assets/brand` أو
`assets/photos` شغّل `node tools/build.mjs` وارفع ما غيّره (`sw.js` وأحيانًا الصفحات) مع التعديل نفسه:
بصمة العمل دون اتصال تُحسب من هذه الملفات، وفحص GitHub يفشل إن لم تُحدَّث. ما يحرره الموظفون من لوحة
الإدارة (`content/` و`assets/uploads/`) لا يحتاج ذلك.

**تعديل نص:** غيّره في `locales/<لغة>.js` أو `data/…/<لغة>.js`، ثم `node tools/build.mjs`.

**إضافة نص جديد:** أضف المفتاح نفسه في الملفات الأربعة، ثم استعمله بـ `t('المفتاح')`، ثم `node tools/build.mjs`.

**إضافة موضوع معرفي:** سطر في `TOPICS` داخل `js/core/site.js`، عنوان `topic.<id>` في `locales/`،
مدخل في `topics` بكل ملف من `data/knowledge/`، ومراجعه في `TOPIC_REFS`، ثم `node tools/build.mjs`.

**إضافة صفحة:** مدخل في `PAGES` داخل `js/core/site.js` وسطر في قائمة الصفحات أعلى `tools/build.mjs`،
ووحدة في `js/pages/` إن كانت نوعًا جديدًا، ثم `node tools/build.mjs`.

**إضافة لغة:** سطر في `LOCALES` داخل `js/boot.js` وفي `LANGS` داخل `tools/build.mjs` و`tools/check.mjs`،
وملف في كل من `locales/` و`data/knowledge/` و`data/history/`، ثم `node tools/build.mjs`.

**تغيير الدومين:** انظر `docs/DOMAIN.md`.

## قبل كل رفع

```bash
node tools/build.mjs
```

```bash
node tools/check.mjs
```

الفحص يفشل برسالة عربية/إنجليزية إذا وُجد:
- في محتوى لوحة الإدارة: ملف تالف، حقل مطلوب فارغ، تاريخ أو مستوى غير صالح، رابط قائمة أو رابط خريطة
  أو صورة أو فيديو لن يظهر في الموقع (القواعد نفسها في `js/core/cms.js` و`js/core/video.js`).
- في النصوص: مفتاح ناقص أو زائد أو غير مستعمل في إحدى اللغات، نص يذكره الكود وغير موجود، أو نص بادیني
  يخالف قواعد الإملاء في `docs/BADINI.md`.
- في الملفات: ملف مشار إليه ومفقود أو مكتوب بحالة أحرف خاطئة، ملف لا يستعمله شيء، ملف غريب في الجذر أو
  صفحة لم يولّدها القالب، استيراد أو مسار يبدأ بـ `/`، تنسيق CSS لعنصر لا يكتبه أي كود، خطأ نحوي في سكربت،
  أو صفحة أو نمط أو وحدة تحمّل شيئًا من موقع آخر عند الفتح.

وينبّه (دون أن يفشل) على: ترجمة خبر ناقصة، تنبيه انتهى وقته، ملف مرفوع ليس صورة.

GitHub يشغّل الأمرين نفسيهما بعد كل تعديل (`.github/workflows/check.yml`)، ويفشل أيضًا إذا كانت الصفحات
المولَّدة أو `sw.js` غير مطابقة لما يكتبه `node tools/build.mjs`.

**العمل دون اتصال:** `build.mjs` يكتب في `sw.js` بصمة لكل ملفات الموقع، فكل تحديث يثبّت عاملًا جديدًا يحذف
النسخة القديمة. الصفحة التي فُتحت مرة تعمل دون اتصال بكل اللغات؛ الصفحة التي لم تُفتح تعرض `offline.html`
(مع زر 115).

**الرابط القانوني (canonical):** يضيفه `js/boot.js` لكل لغة (`?lang=` لغير العربية)، لا القالب.

**ورقة المراجعة اللغوية** (عربي ↔ لغة أخرى، لكل نصوص الموقع):

```bash
node tools/review.mjs badini
```

## ما هو غير مفعّل عمدًا

- **الحسابات وتسجيل الدخول** (`account.html`): واجهة تجريبية فقط؛ لا يُرسل ولا يُحفظ شيء.
- **الطلبات** (`portal.html`): مسودات تُحفظ في متصفح الزائر (`cd-drafts-v1`) ولا تُرسل للمديرية.
- **صفحات المعرفة والتاريخ**: موسومة `noindex` ما دام `draftContent: true` في `site.config.json`،
  إلى أن يعتمد مختص محتواها؛ عندها غيّرها إلى `false` وشغّل `node tools/build.mjs`.

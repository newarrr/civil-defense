# التشغيل والأمن والقرارات المطلوبة

الحالة الحالية: لا موظفون حقيقيون ولا خدمات إنتاج جديدة. النواة والمعاينة المحلية أدوات مراجعة، وليستا بوابة بلاغات أو إدارة متاحة للعامة.

## مصفوفة الأدوار

| الدور | صلاحية النواة |
|---|---|
| super_admin | إدارة النظام والموظفين والتحرير والمراجعة والنشر؛ منع المراجعة الذاتية دائم |
| admin | إدارة الموظفين والتحرير والمراجعة والنشر؛ لا manage_system |
| editor | قراءة وتعديل مسودة وتقديم؛ لا اعتماد أو نشر |
| reviewer | قراءة وبدء مراجعة وإعادة مع سبب واعتماد مادة غير مؤلفه |
| publisher | قراءة ونشر المعتمد وأرشفة المنشور؛ لا تعديل أو اعتماد |
| translator | قراءة وصلاحية ترجمة منفصلة؛ حفظ مهمة الترجمة عبر API لاحق |
| subject_expert | قراءة ومراجعة علمية؛ ليست موافقة تحريرية أو نشراً |
| media_manager | قراءة وإدارة وسائط؛ رفع/فحص فعلي مؤجل |
| auditor | قراءة وسجل إجراءات؛ لا انتقالات كتابة |

الأدوار تُقرأ من قاعدة البيانات بعد التحقق من identity_subject، ولا تُقبل من token claims وحدها أو حقول الطلب. إضافة دور مجهول ترفض الهوية في نواة الصلاحيات. إيقاف الموظف يسري عند الأمر التالي. لا super_admin يتجاوز شرط استقلال المراجع. حسابات الاختبار اصطناعية داخل قاعدة مؤقتة تختفي بعد الاختبار.

## تشغيل التحرير المستهدف

1. محرر ينشئ مسودة ويحدد النوع والنطاق والمصادر والأبعاد الأربعة.
2. خبير يراجع الادعاءات وإصدار المعيار والحدود المهنية، ومترجم/مراجع مستقل يراجع كل لهجة؛ لا اعتماد machine-only.
3. محرر يقدم؛ مراجع مستقل يبدأ مراجعة ثم يعتمد أو يعيد مع سبب.
4. ناشر يعيد فحص المراجعات والمصادر الحالية وmissingFields والخصوصية قبل النشر. حفظ المعاملة والتدقيق شرط، وإذا فشل أحدهما فلا نشر.
5. exporter يبني artifact عاماً، بفصل وقت الحدث عن النشر. جميع التواريخ تعرض Asia/Baghdad دون تغيير الحقيقة المخزنة UTC.
6. التصحيح إصدار جديد ومراجعة جديدة؛ الخبر لا يُعدّل بصمت. الأرشفات تستبعد من النتائج الجارية وتبقي سياسة URL وتصحيح معلنة بعد اعتمادها.

المنفذ الآن هو نواة الانتقالات وخدمة معاملاتها، لا واجهات الخطوات أو مهام المترجمين. لا يجوز منحها إنترنت قبل اكتمال التحقق أدناه.

## نموذج التهديد وضوابط قبل الإنتاج

| الخطر | الضابط المطلوب | المنفذ الآن |
|---|---|---|
| تزوير دور/اعتماد ذاتي | هوية موثوقة وأدوار DB وفصل المؤلف | النواة وخدمة الأوامر تختبران ذلك؛ موفر الهوية غير مربوط |
| API bypass/SQL injection | DTO allow-list ومعاملات parameterized، حساب DB محدود، RLS/وظائف محددة | allow-list/parameters/policy موجودة؛ grants التطبيق/RLS الإنتاج مؤجلة |
| فقد تحديث/نصف نشر | row lock/version وtransaction مع revision/audit | اختبارات DB ناجحة بما فيها rollback عند فشل audit |
| تعديل التدقيق | append-only DB، صلاحيات محدودة وتصدير خارجي مستقل | triggers محلية؛ لا ادعاء مقاومة DBA/superuser |
| تسريب مسودات | بوابة export ومنع source/translation غير معتمدة وعلاقات مسودات | نواة export موجودة؛ pipeline الإنتاج مؤجل |
| سرقة جلسة/CSRF | HTTPS، MFA، HttpOnly/Secure/SameSite، CSRF، CORS أصل محدد | لا جلسات أو HTTP API؛ متطلبات قبل الربط |
| رفع ضار | MIME signature، حد حجم، AV، حجر خاص، إعادة ترميز صور، إزالة EXIF/GPS | لا upload متاح؛ لا زر مضلل |
| XSS/روابط ضارة | textContent في المعاينة، HTTPS source URL، CSP وnosniff | موجودة في الخادم المحلي؛ Markdown sanitizer مطلوب للمحرر المستقبلي |
| بيانات عمليات حساسة | قواعد تصنيف ومراجعة خصوصية وتقليل/تجميع | لا بيانات تشغيلية مضافة؛ تصدير public فقط |
| أعطال/فقد بيانات | نسخ مشفرة خارج المشروع واستعادة staging وتنبيهات وتحديد RPO/RTO | غير منفذ بلا backend معتمد |

رفض أوامر API يحتاج سجل أمني منفصلاً دون إدخال كلمات مرور أو tokens، وحد طلبات لكل هوية/شبكة وإلغاء جلسات وتحقق server-side فعلي. لا يمكن اعتبار test adapter مصادقة إنتاج. PGlite لا يختبر TLS أو موفر الهوية أو ربط connection pool أو تزامن عدة خوادم أو PostgreSQL production RLS.

## التخزين والاحتفاظ والتعافي

تحديد مسؤول بيانات ومشغل احتياطيات قبل التشغيل. اقتراح للمراجعة: نسخ DB يومية مشفرة + وسائط بإصدارات + نسخة خارج حساب الإنتاج؛ اختبار استعادة قبل الإطلاق ثم دورياً، بمقارنة عدد الصفوف وchecksums وعينة صلاحيات ومراجعات. RPO/RTO وفترة الاحتفاظ يحددها المالك، ولا يُدّعى رقم ضمان حالياً. لا تسجل هوية المصابين أو الموقع الدقيق للحوادث في منصة المعرفة. سجلات الأمان لا تحفظ الأسرار أو أجسام الطلبات الحساسة.

## قرار الخدمة الخارجية — مطلوب قبل المرحلة التالية

الخيار المفضل للمراجعة: PostgreSQL/Auth/Storage مُدار (مثل Supabase Pro)، وAPI منفصل وموقع الإدارة الخاص. بديل: استضافة الجهة مع PostgreSQL وOIDC وتخزين وفريق تشغيل. يلزم قرار واضح حول:

- الجهة المالكة للحساب والفوترة، الميزانية، منطقة البيانات وسياسة السيادة.
- موفر دخول الموظفين وMFA وآلية إثبات الموظف واسترداد الحساب ومسؤول super_admin.
- مشغل API والإدارة، النطاق/البريد، إدارة الأسرار، تنبيهات الأعطال والنسخ.
- RPO/RTO والاحتفاظ، تراخيص المواد، المراجعون المخولون محلياً وعلمياً ولغوياً.

لا حسابات أو اشتراكات أو DNS أو secrets تُنشأ قبل موافقة. لا ترحيل framework مطلوب. لا تعديل رئيسية لإضافة رابط حتى يأتي اعتماد منفصل.

## سجل البيانات الناقصة

| الحقل/المجموعة | المصدر المطلوب | الحالة/أثر النشر |
|---|---|---|
| الاسم الرسمي، الشعار، حدود الهوية | كتاب/أصل معتمد من المديرية | بانتظار توثيق؛ الأصول الحالية محفوظة |
| تأسيس دهوك والمراكز والتسلسل المحلي | قرارات رسمية ووثائق أرشيفية مرخصة | لا تواريخ افتراضية أو ربط تلقائي بتأسيس ICDO |
| الهيكل والأسماء والاتصالات والخدمات | بيانات مديرية مع تاريخ اعتماد | لا إدخالات موظفين أو أرقام جديدة مخمنة |
| جرد المعدات/الإحصاءات/أخبار يومية | بيانات مصرح بنشرها واعتماد المصدر | لا جرد محلي أو أخبار اختبار في الجمهور |
| الترجمات البادينية والسورانية | مراجع بشري مستقل لكل لهجة ومعجم | كلها pending؛ لا تأكيد إملاء100% آلياً |
| محتوى السلامة والمعايير | خبير ومصدر أولي وطبعة/نطاق/ترخيص | لا اعتماد علمي افتراضي |
| الصور/الخرائط/الأطلس | ترخيص وسند وبيانات عامة مراجعة | لا صور AI أرشيفية أو بيانات مواقع عمليات |

## النشر والتراجع

الفرع فقط؛ لا merge أو deployment في workflow الجديد. Pages يبقى على main. النشر يحتاج مراجعة PR وموافقة المالك ثم فحص artifact، مع إمكانية العودة لإصدار معتمد سابق. لا يُعتبر إنشاء PR إذناً بالدمج. تعطيل/تشغيل خدمات أو تغيير branch protection يحتاج قراراً إدارياً؛ لم يُدّع تفعيله.
